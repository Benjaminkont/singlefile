# 网页翻译 SOP：保留原页，只替换文字

## 1. 目标与已确认样页

翻译以已归档的原始 HTML 为底稿，在原有文本节点内替换文字，另存中文副本。保留原页的结构、样式、资源和已有交互，不重新排版。

用户已确认的样页：

- [中文：《构建有效的智能体》](../archives/anthropic.com/pages/zh-CN-research-building-effective-agents-38c43325a5.html)
- [对应英文原页](../archives/anthropic.com/pages/research-building-effective-agents-38c43325a5.html)
- 样页工作记录与截图在本地生成，不随本公开仓库上传。

后续页面以这篇样页的处理方式为标准。中文自然改变换行、段落高度和整页长度是正常现象；不能因此删减翻译、压缩内容或修改样式。

## 2. 修改边界

| 内容 | 处理规则 |
| --- | --- |
| 浏览器标题、正文标题、段落、列表、表格文字、图注、脚注、附录、致谢 | 完整翻译，保留原位置及标签关系 |
| 目录、页眉、页脚、导航、已有按钮的文字 | 在原节点内翻译，不新增控件 |
| 段内链接、加粗、斜体、上下标 | 保留标签和属性，只翻译其中适合翻译的文字 |
| DOM 标签、顺序、层级及属性 | 保持原样；包括 class、id、style、href、src、data-* 等 |
| CSS、字体资源、JavaScript、结构化数据 | 保持原样 |
| 图片、SVG、图表及图内文字 | 保持原样；图片外的图注仍要翻译 |
| 代码、命令、公式、路径、API 名称、标识符 | 保持原样，不按普通文字翻译 |
| 产品名、人名、书目信息等 | 保留必要原文，术语保持一致，不擅自改名 |

本流程不修改属性，因此原页的 `lang`、`alt`、`aria-label` 等也保持原样。若后续需要本地化这些属性，应作为明确的额外范围处理并单独记录，不能混入“只有文字节点改变”的验收结果。

## 3. 准备原页与任务清单

1. 确认待翻译的英文 HTML 能离线阅读，记录准确路径、文件大小及 SHA-256。
2. 明确本批文件清单；归档任务若仍在新增页面，不自动扩大翻译范围。
3. 输出使用同目录中的 `zh-CN-<原文件名>.html`，以保留原有相对链接的解析位置。英文原页不得覆盖。
4. 阅读原页及其上下文。`texts/` 里的提取文本只能辅助理解，不能作为重建页面的输入；它可能丢失链接边界、表格结构、上下标和公式格式。
5. 首次处理新站点或明显不同的页面模板时，先完成一篇包含代表性结构的样页，检查通过后再批量处理。

## 4. 提取与对应文本节点

使用能报告源码位置的 HTML 解析器识别文本节点，记录节点编号、起始位置及原始文本。解析器用于定位，不能将整个 DOM 重新序列化作为输出。

推荐节点记录：

```json
{
  "id": 47,
  "start": 123456,
  "source": "原始文本节点内容",
  "translation": "对应中文译文"
}
```

- 跳过 `script`、`style`、`svg`、`pre`、`code` 内部内容；还要识别普通标签中的公式及技术标识符，不能仅靠标签判断。
- 保留空白和 HTML 实体。使用源码偏移替换时，实体应保持在原位置，或被明确纳入可追踪的文本范围；不能在解码后沿用未经换算的偏移。
- 使用与提取时完全一致的源字符串和偏移单位。不要混用字节偏移与字符偏移，也不要在提取后先规范化换行。
- 被链接、强调等标签拆开的句子，应将相邻节点一起阅读、一起翻译，再分别填回。不能独立翻译碎片后生硬拼接。
- 节点可以因中文语序而承载不同长度的片段，但链接及强调的文字仍应对应它们原先表达的概念。确实无需保留的英文冠词等片段可以变为空字符串，必须记录原因，不能把空译文一律视为漏译或一律忽略。

## 5. 翻译与审校

1. 完整翻译内容，不概括、不合并删节，不把长段改为摘要。
2. 保留事实、数字、单位、比较对象、因果关系、实验条件和限制。尤其区分“可能”“表明”“证明”，不能提高原文结论的强度。
3. 阅读整句及上下段后确定译法。统一关键术语，例如同篇中的 agent、workflow、orchestrator、evaluator。首次出现可酌情保留英文术语。
4. 检查段内标签两侧拼接后的中文，避免重复标点、缺少连接词、链接错位或强调对象改变。
5. 回查 HTML 中的指数、下标和公式。例如 `2<sup>64</sup>` 不能按提取文本中的 `264` 理解。
6. 完成正文后检查目录、图注、脚注、附录、致谢及页眉页脚。保留原文的动态内容限制，不臆造归档中不存在的内容。
7. 百分比核对、英文残留扫描、长度比例检查用于定位疑点，不能单独证明翻译准确或不准确。对疑点必须读原文审校。

允许并行时，可以按章节或连续节点区间分工。每位执行者只写独立结果文件，由一个合并者检查编号、覆盖范围、术语及跨区间句子，避免同时覆盖同一译文文件。

## 6. 写入中文副本

按源码位置从后向前替换文本，避免前面的改动使后续偏移失效。每次替换前，断言源字符串在该位置的内容与记录的原文完全一致；不一致就停止并重新提取，不能猜测匹配位置。

替换文字需要进行 HTML 文本转义，避免译文中的 `&`、`<`、`>` 变成实体或标签。不通过修改 `innerHTML` 填充翻译，也不使用全局字符串替换，以免误改脚本、样式、属性或重复出现的文本。

完成后写入中文副本，并重新计算英文原页哈希，确认未被改动。未完成文件不得标记为完成或进入正式入口；再次运行默认应识别已有译页，避免无意覆盖已审校版本。

## 7. 验收：结构、内容、视觉分别检查

### 7.1 结构与资源

以英文原页为对照，检查：

- 标签数量、顺序、层级及全部属性一致。
- CSS、脚本、嵌入字体、图片、SVG、代码和公式保持一致。
- 除记录中的翻译文本范围外，源码其他部分完全一致。只比较标签数量不足以证明没有误改。
- 源文件哈希未变，节点编号无重复或遗漏；保留原文或留空的节点有明确理由。
- 本地链接目标仍可访问，章节锚点 ID 未变。

### 7.2 内容

通读译文，核对标题、目录、所有正文章节、图注、脚注、附录及致谢。检查关键数值、否定词、限定语、术语和代码边界。不得仅凭“JSON 可解析”“节点数相同”或子 agent 的完成报告宣称翻译合格。

### 7.3 浏览器与视觉

在同一个浏览器、相同视口和缩放下离线打开英文与中文页面：

1. 等待字体与图片加载，检查图片失败情况；原页已有问题应单独记录。
2. 对照顶部、中部、底部，并针对每个主要章节及图表、表格、代码区检查。按整页高度百分比截图只能用于快速浏览，不能代替对应内容的比较。
3. 检查原有分栏、正文宽度、图片位置、标题层级、列表、间距和页眉页脚。
4. 检查窄屏下文字、按钮和导航是否溢出，图片是否完整。
5. 检查目录跳转、已有链接以及原页可用的交互。结构保留不等于交互已经验证。
6. 允许中文自然重排；若出现截断、遮挡或溢出，先检查翻译及原布局约束。确需改样式时，单独说明并取得范围确认，不能偷偷修改 CSS。

## 8. 交付与记录

交付时提供中文样页和英文原页的直接链接，说明翻译覆盖范围、检查结果以及图片中文字等保留项。只声明实际执行过的验证，不把抽查说成逐字复核，不把结构一致说成像素位置完全相同。

证据保存在站点的 `records/` 下，包括源文件路径和哈希、节点与译文映射、检查结果及对照截图。样页工作记录可放在 `records/translation-sample/`，公开版本不提交这些工作文件。批量任务应使用独立批次目录，记录每页状态，避免覆盖样页证据。

中文页是英文归档的派生副本，不伪造抓取成功记录，也不为了显示译文而把它注册成一个新原站 URL。若需要目录入口，应单独维护翻译映射，并确保更新目录后不会丢失。

## 9. 明确禁止的做法

- 从纯文本或 Markdown 重建一套新的 HTML 阅读页。
- 更换原页面 CSS、字体、布局、图文顺序，或把插图统一挪到文末。
- 新增英文对照按钮、翻译说明栏等原页没有的界面。
- 将整段含链接、加粗或上下标的内容拍平后覆盖。
- 为适应原高度而删节译文、缩小字号或强制固定段落高度。
- 未核对源码边界就全局替换英文，或重新序列化整页导致大量无关变化。
- 复用已被用户否定并要求删除的旧译文作为底稿。

## 10. 已确认样页的实际结果

《构建有效的智能体》样页为236个文本节点记录了译文或保留原文的处理结果，其中229个节点实际发生文字变化；另保留8个目录编号节点；源码中的其他空白、实体及跳过区域保持原样。浏览器检查确认：标签及属性、CSS、脚本和图片一致，9张可见图片无损坏，附录与致谢存在，390像素视口下无横向溢出。另已查看桌面顶部、中部、底部及手机截图。

这些结果是本篇的验收证据，不自动适用于其他文章，也不表示原站的所有动态交互都可离线使用。
